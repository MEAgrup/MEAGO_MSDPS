### 3c. `auth_users_token_defaults` — paling berisiko, dan tidak butuh keputusan apa pun

Tercatat di riwayat kedua environment sebagai `0318_auth_users_token_null_guard`, tapi
`git log --all -- 'supabase/migrations/0318*'` **kosong** — filenya tidak pernah ada.
`grep -rn "auth_users_token_defaults"` di seluruh repo juga **nol hasil**.

Isinya trigger `BEFORE INSERT OR UPDATE ON auth.users` yang mengubah 8 kolom token GoTrue
dari NULL menjadi string kosong (`confirmation_token`, `recovery_token`,
`email_change_token_new`, `email_change_token_current`, `email_change`, `phone_change`,
`phone_change_token`, `reauthentication_token`). Ini penangkal bug GoTrue
*"converting NULL to string is unsupported"* yang muncul saat user dibuat lewat SQL/admin API.

**Kenapa ini penting sekarang:** jalur pembuatan akun Portal Kreator
(`createCreatorAccount` di `lib/actions/portal.ts`) memakai admin API. Di environment baru
hasil `db reset` — tanpa trigger ini — pembuatan akun berpotensi gagal dengan error yang
sama sekali tidak menunjuk ke penyebabnya. Dan itu tepat jalur yang harus dipakai untuk
membuka blocker item 2.

Perbaikannya tidak butuh keputusan bisnis: cukup resmikan apa adanya ke file migrasi
(idempoten, no-op di kedua environment yang sudah punya). Belum dikerjakan di sesi ini
karena permintaannya laporan, bukan perubahan skema.

### 3d. `update_poi_realisasi` — nasibnya terikat keputusan item 5

## 7. Cara memeriksa ulang

Paritas dua environment — **bandingkan HASH, bukan JUMLAH**, dan **normalisasi definisi
fungsi dulu** (buang komentar `--` + whitespace), kalau tidak akan muncul 26 "fungsi
berbeda" palsu:

```bash
psql -h /tmp -p 55432 -U postgres -d msdps_reset -tAq \
  -f scripts/schema_fingerprint.sql | LC_ALL=C sort > /tmp/fp_local.txt
# jalankan isi file yang sama lewat MCP Supabase execute_sql di staging & production
LC_ALL=C diff /tmp/fp_staging.txt /tmp/fp_prod.txt
```

**Dan bandingkan juga ke database bersih hasil repo**, bukan hanya dua environment satu
sama lain. Kalau langkah itu dilewat, temuan §3 tidak akan pernah muncul.
