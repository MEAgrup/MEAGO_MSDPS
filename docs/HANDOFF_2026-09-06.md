## 4. Jebakan yang WAJIB dihindari

Daftar penuh di `docs/HANDOFF_FaseG.md` §7. Yang paling sering menggigit, plus tiga yang
baru ketemu sesi ini:

1. **Nomor migrasi berikutnya tidak pernah "aman"** hanya karena file terakhir bernomor N.
   Cek `git log`, `git branch -r`, **dan** riwayat migrasi kedua environment.
2. **`pg_test_reset.sh` lolos ≠ environment setara.** Bandingkan **HASH**, bukan JUMLAH,
   dan **normalisasi definisi fungsi dulu** (buang komentar `--` + whitespace) — tanpa itu
   muncul 26 "fungsi berbeda" palsu. Bandingkan juga ke **database bersih dari repo**,
   bukan hanya dua environment satu sama lain: kalau keduanya sama-sama menyimpang dari
   repo, diff antar-environment terlihat bersih dan menipu. **Itulah yang terjadi sampai
   2026-09-05.**
3. 🆕 **JANGAN meringkas sidik jari jadi satu hash agregat di dalam SQL.** `order by`
   mengikuti collation database (reset lokal `C.UTF-8` vs Supabase `en_US.UTF-8`) — isi
   IDENTIK bisa menghasilkan hash berbeda. Keluarkan satu baris per objek, urutkan dengan
   `LC_ALL=C sort` **di luar** database, lalu diff. Sudah dicatat di
   `scripts/schema_fingerprint.sql`.
4. 🆕 **`least()` mengabaikan NULL** — `least(null, 100)` = **100**, bukan null. Pernah
   membuat deal yang jumlah kreatornya belum diisi mendapat poin penuh.
5. 🆕 **Nama migrasi tidak membuktikan SQL apa yang dijalankan production.** 14 file repo
   sudah diedit sesudah diterapkan (terbesar `0344` +733 karakter). Kalau perlu tahu SQL
   yang benar-benar jalan, baca kolom `statements` di `schema_migrations`.
6. **Setiap perubahan skema live WAJIB punya file migrasi** — termasuk perbaikan cepat
   lewat SQL Editor.
7. **`ALTER TYPE … ADD VALUE` harus migrasi terpisah** (aturan rumah `0300:5-8`).
8. **React 19/Next 15: `name`/`value` tombol submit tidak masuk FormData** — satu `<form>`
   per aksi + hidden input.
9. **`npm run build` JANGAN saat `npm run dev` menyala.**
10. **Jangan pakai `brand_deals.shop_id`** untuk merchant target campaign — pakai
    `target_location_id` (TikTok Location ID).
11. **Kunci merchant di file TikTok = `Location ID`**, bukan kolom `Merchant` (itu daftar
    OTA) dan bukan `Location name`.
12. **Ingest DILARANG auto-create kreator.**
13. 🆕 **Hash fungsi MENTAH yang berbeda belum tentu drift — dan "cuma 21 dari 22 kosmetik"
    bukan alasan berhenti.** Bandingkan versi **ternormalisasi** (buang komentar `--` +
    seluruh whitespace) satu per satu. Pada 2026-09-06, 22 fungsi berbeda hash mentahnya
    antara staging dan production; 21 murni kosmetik, **satu drift sungguhan** yang lolos
    dari pemeriksaan sebelumnya karena hasilnya diringkas jadi "beda kosmetik" tanpa
    memeriksa sisanya. Lihat `0357`.
14. 🆕 **Ringkasan sidik jari agregat harus kebal urutan.** `sum()` atas potongan hash
    (`('x'||substr(md5(...),1,8))::bit(32)::bigint`) aman; `md5(string_agg(... order by ...))`
    tidak — itu jebakan collation di poin 3.
15. 🆕 **"SOP 15/15 selesai" menyesatkan.** `poi_sop_ensure_progress()` membuat 15 baris
    **di muka**; yang menandai selesai adalah `completed_at`. Hitung
    `count(completed_at)`, bukan `count(*)`.

## 5. Batas model data yang sudah diketahui

**Dining Berbayar bisa mencapai 100% dengan memutar kreator yang sama.** Yang dicatat per
siklus adalah **jumlah** kreator, bukan identitasnya. Dengan target per-deal dan akumulasi
lintas bulan, kreator yang dipesan ulang bulan berikutnya terhitung dua kali. Tidak bisa
ditambal di formula — perbaikannya mencatat identitas kreator per siklus (tabel
penghubung). Belum mengganggu (0 data nyata), dicatat supaya tidak ditemukan lagi dari nol.
